# 采核助手

面向黑客松演示的本地采购文档审核应用。React + TypeScript + Vite 前端，FastAPI 后端，SQLite 持久化，文件保存在本机。已实现创建任务、文档导入、结构化抽取、人工修正、规则核对、证据查看、人工处理、Word 报告闭环。页面和样例均为中文。

## 启动

首次从 GitHub 克隆后，需要安装依赖、构建前端，并创建本机登录配置：

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m backend.auth --username OS-HUBU
cd frontend
npm ci
npm run build
cd ..
```

按提示设置自己的登录密码。API Key 可选：复制 `config.local.example.toml` 为 `config.local.toml` 并填写。真实密钥、登录配置、任务数据库、上传文件、依赖目录、构建产物、缓存及交付 ZIP 均不会提交到仓库。

需要 Python 3.11+、Node.js 20.19+。在当前目录打开 PowerShell，优先使用启动脚本：

```powershell
./start.ps1
```

脚本复用现有 `.venv`，缺少依赖时安装，缺少前端构建时构建；检测到本项目已运行时直接显示网址，不重复启动。访问 http://127.0.0.1:8000 。

手动安装和启动（已有 `.venv` 时跳过创建）：

```powershell
if (-not (Test-Path '.venv/Scripts/python.exe')) { python -m venv .venv }
.venv/Scripts/python -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
.venv/Scripts/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

安装源不可用时可给 pip 加 `-i https://pypi.org/simple`。

如果重复运行 `python -m venv .venv` 出现 `Unable to copy ... venvlauncher.exe ... python.exe`，先检查 http://127.0.0.1:8000 是否已可访问。这通常是运行中的后端占用了虚拟环境的 Python；已有环境无需重建。直接打开网页或执行 `./start.ps1` 即可。确需重建时，先在启动服务的终端按 Ctrl+C 停止服务，再操作；不要删除仍被使用的环境。

前后端开发分开运行：后端命令添加 `--reload`；另一个终端执行 `cd frontend`、`npm run dev`，访问 http://127.0.0.1:5173 。Vite 将 `/api` 代理到 8000。前端修改后要重新构建、重启后端，才能在 8000 看到新版；开发模式则自动更新。

## 五分钟演示

打开应用先进入登录页，使用已配置的账号登录；右上角可退出。当前本地账号为 `OS-HUBU`，密码已按本次要求配置，不写入源码或前端包。刷新页面会保留有效会话，默认 8 小时后过期；退出后服务端会立即撤销当前会话。

页面按六步逐级解锁：创建任务 → 上传并提交三类材料 → 抽取与修正 → 交叉核对 → 人工确认 → 导出报告。材料未提交时不允许抽取，字段未确认时不允许核对，核对未执行时不展示问题列表、结果指标或报告入口。前后端都校验顺序，跳步请求返回 409 和具体提示。当前主页面只展示该阶段内容；材料管理、修改记录、调用记录和报告预览在独立弹窗内，问题详情使用侧边弹窗，原文与字段修正支持嵌套弹窗。Esc 关闭当前层，键盘焦点限制在当前弹窗内。

字段抽取完后点击“已核对字段，进入下一步”；自动核对后逐条处理问题，再点击“确认已完成人工复核”，最后通过报告预览导出。自动通过也需要整体人工确认；确认不代表异常已消除。确认状态保存到数据库，刷新不会丢失；替换材料会退回提交步骤，字段修改会撤销字段确认和审核结果，重新核对会撤销整体人工确认。核对后、整体确认前可导出明确标注人工复核未完成的过程报告。

1. 点击工作台右上角“演示中心”，在弹窗中选择“载入 A 组 · 一致”（样例已提交并预设抽取），确认字段后点击“开始交叉核对”：三类材料一致，结果为“通过”，无预设异常。样例文件下载也集中在演示中心。
2. 再次打开“演示中心”，点击“载入 B 组 · 异常”，确认字段并开始核对：显示 9 条问题，覆盖 6 类预期规则。型号、数量和交付冲突会分别与需求、报价交叉比较，因此同一根因可能有多条问题。
3. 点击“型号不一致”行，查看双方原文及 DOCX 段落位置，打开完整原文；填写备注并保存“已确认”或“误报”。自动检测和人工状态分别保留。
4. 在“材料管理”弹窗点击“修正字段”；原文与字段并排展示。保存后记录修改前后内容，旧审核结果失效，需重新确认字段并核对。
5. 点击“审核报告”，在预览弹窗中导出过程或最终报告。报告含任务、材料、范围、自动问题、原文位置、人工状态、备注、修改记录及未完成检查。
6. 底部下载 A/B 组 ZIP，各含 3 份 DOCX 及人工标注清单。它们由与抽取结果一致的确定性样例生成器生成，字段证据会通过原文验证。
7. 新建真实任务并上传文件：支持文本 PDF 和 DOCX，单份最多 10 MB，每类一份；删除后可重新上传。三类文件齐备且可解析后点击“提交材料，进入抽取”，再提取关键信息。无密钥时明确失败，可查看解析原文并人工录入；不会把用户文件识别为样例。损坏文件、空文档和扫描件独立显示失败。

**演示数据使用预设抽取，不能用来宣称真实模型准确率。** 真实上传即便与样例文件内容相同，也不走预设结果。

## 模型配置

默认接入 DeepSeek 官方 API。项目已提供两个后端配置文件：

- `config.toml`：公共参数，默认基址 `https://api.deepseek.com`、模型 `deepseek-flash`、超时 40 秒、最多 2 次尝试、最大输出 8192 tokens。模型名称可按账户实际可用模型修改。
- `config.local.toml`：仅本机密钥，已加入 Git 忽略。开发目录已创建空文件；新克隆项目时从 `config.local.example.toml` 复制。

在 `config.local.toml` 中填写（不要把真实密钥写进公共文件）：

```toml
[model]
api_key = "在这里填写你的 DeepSeek API Key"
```

然后执行 `./start.ps1`。本次升级若仍运行旧后端，请先在原启动终端按 Ctrl+C 停止后再启动；填写密钥后的日常配置文件修改会在下一次请求读取，刷新页面即可更新模式提示。没有密钥时继续明确显示“演示模式”。配置有误会显示“配置错误”，不会伪装成正常演示。

优先级：环境变量 > 本地配置 > 公共配置 > 内置默认值。`.env` 为可选的环境变量文件，仍支持旧环境变量；如果填了本地密钥却仍处于演示模式，请检查是否存在空的 `MODEL_API_KEY` / `DEEPSEEK_API_KEY` 环境覆盖。

| 变量 | 说明 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 可选密钥覆盖，优先于旧的 `MODEL_API_KEY` |
| `MODEL_API_BASE` | 可选 API 基址覆盖；系统追加 `/chat/completions`，请勿填写完整接口路径 |
| `MODEL_NAME` | 可选模型名称覆盖，须支持 JSON 对象输出 |
| `MODEL_API_KEY` | 兼容旧环境变量；不使用覆盖时请删除或注释，不要留一个空变量覆盖本地配置 |
| `CAIHE_CONFIG_FILE` | 可选公共 TOML 文件路径，本地配置读取该路径旁的 `config.local.toml` |
| `DATA_DIR` | 可选，本地数据目录，默认项目下 `data` |

修改环境变量或 `.env` 后重启后端。密钥不下发前端，不写入数据库或日志；`.env` 与 `config.local.toml` 均已忽略。配置校验报错不会包含配置原文或密钥。前端配置接口仅返回供应商、模型名和是否已配置等公开状态，不返回密钥或基址。

真实模型接入在 `backend/extract.py`，配置读取与校验在 `backend/settings.py`。采用 Bearer 鉴权和 `/chat/completions`，按 [DeepSeek 官方 JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/) 发送 `response_format={"type":"json_object"}`、JSON 示例和输出长度限制，随后在本地校验结构与逐字证据。超时、网络失败、429 及部分 5xx 有限重试，其余错误立即返回；401 提示密钥无效，402 提示余额不足，输出截断也明确失败。不回显上游正文或凭据，不静默切换成样例。

`requirements-lock.txt` 记录本次 Windows Python 3.13 验证环境（含渲染 QA 辅助依赖）；如需复现可使用该文件代替 `requirements.txt`。前端依赖由 `package-lock.json` 锁定。

模型收到独立系统指令：文档内容属于不可信数据，不得改变审核规则或执行操作。模型无工具执行权限，仅输出抽取 JSON；Pydantic 校验类型、拒绝额外字段，原文引用逐字匹配指定页或段落。该校验验证证据存在，不保证模型语义理解正确，用户仍须核对。

## 登录账号配置

认证配置保存在 `auth.local.toml`，已加入 Git 忽略。只存储账号、PBKDF2 SHA-256 加盐密码哈希和会话时长，不保存明文密码。当前工作目录已配置完成；新克隆的项目或需要修改密码时运行：

```powershell
.venv/Scripts/python -m backend.auth --username OS-HUBU
```

按提示输入两次密码（终端不回显）。可通过 `CAIHE_AUTH_FILE` 指定其他认证文件路径。账号或密码哈希改变后，已有会话在下一次请求失效，不需要重建虚拟环境。`session_hours` 可设为 1–24，默认 8；该账号是首版单账号登录，不提供注册、多角色或找回密码。

登录由后端校验。所有业务 API（含文档下载、样例下载、调用记录、报告导出）均要求有效会话，未登录返回 401；页面及公开健康检查不需要登录。会话随机令牌写入 HttpOnly、SameSite=Strict Cookie，服务端 SQLite 只保存令牌哈希，退出会删除记录；HTTPS 时 Cookie 同时使用 Secure。写请求验证 Origin，错误账号或密码统一提示，连续 5 次失败会限制该来源 5 分钟。日志不记录登录请求正文、密码或 Cookie。

## 规则与状态

- `DOC-001` 必要材料缺项；上传但解析或抽取失败的材料不会被误报为“未上传”。
- `FIELD-001` 成功抽取文档的必要字段；采购需求不要求供应商或报价金额，报价和合同要求供应商、币种、税费等。
- `MATH-001/002` 数量乘单价、分项合计采用 Decimal；默认误差 0.01，可在页面修改。非有限、负数、过大数值（超过 1e24）或超过 12 位小数不进入运算，列为未检查。使用 80 位精度避免浮点误差。
- `ITEM-001/002/003` 型号、数量和单位交叉核对；优先明确型号或规范化名称，仅在唯一匹配时比较。名称一致但型号不同可作为候选并产生型号问题；相似名称、重复候选或无明确对应关系使用 `MATCH-001` 人工确认，不强行关联。首版不提供自动模糊匹配或手动映射持久化界面。
- `PARTY-001` 仅报价与合同互核供应商。
- `DATE-001` 精确日期表示单日，最晚日期表示截止范围，范围无交集才判冲突；`DATE-002` 相对日期或无法解释的日期待复核，不把文字不同直接当冲突。相对交期的基准事件与工作日历不自动推断。
- `BASIS-001` 币种、税费和单位不明或不一致时待复核，不做直接金额比较。`PRICE-001` 同口径商品单价、分项金额差异；`TOTAL-001` 同口径总金额差异。保守使用规范化原文相等，不自动汇率转换或计算税额。
- 文档“未抽取 / 抽取失败 / 已抽取”，审核“未检查 / 抽取失败 / 通过 / 发现异常”，问题人工“待处理 / 已确认 / 误报”各自独立。人工修正会清空当前审核结果，旧结果存入历史；重新核对产生新问题，人工判断需要重新确认。
- 每个字段的文档 ID 由所属文档记录绑定；引用保留逐字原文和 PDF 页码或 DOCX 段落／表格行。无引用的人工录入明确标注，不伪装成原文。

## 查看真实 API 调用日志

有三种入口：

1. 流程卡片下方“当前任务”一栏右侧的绿色“调用记录”按钮：打开独立弹窗，每 3 秒刷新当前任务最近 300 条模型事件。展开详情可查看完整调用编号、后端请求编号、模型、尝试次数、上游 HTTP 状态、耗时、返回的 token 用量及失败原因。长时间处理时会自动打开悬浮进度窗，也可直接点其中的“查看调用记录”。进度窗展示实际等待时间，不估算百分比；可收起为右下角小窗，收起或查看日志不会取消处理，结束后自动消失。短于 400ms 的操作不会弹窗，避免闪烁。
2. 启动后端的终端：实时输出 JSON 事件，同时保留 Uvicorn 的接口访问日志。
3. 本地 `data/logs/api.jsonl`：UTF-8，每行一个 JSON 事件，单文件 5 MB，保留 3 个轮转备份。设置 `DATA_DIR` 后，目录改为该路径下的 `logs/`。

另开 PowerShell，在项目目录实时查看：

```powershell
Get-Content .\data\logs\api.jsonl -Encoding UTF8 -Tail 30 -Wait
```

按页面错误提示中的调用编号检索完整链路（替换下面编号）：

```powershell
Get-ChildItem .\data\logs\api.jsonl* | Select-String -SimpleMatch '替换为调用编号'
```

事件含义：

| 事件 | 含义 |
| --- | --- |
| `http.completed` | 浏览器到后端的请求，含请求编号、路由模板、状态和耗时，不保存查询参数 |
| `model.started` | 开始一次抽取处理；不代表已发送网络请求 |
| `model.request` | 准备发送真实模型请求，含目标接口、模型、超时、输出限制和尝试次数 |
| `model.response` | 收到上游 HTTP 响应，含状态、耗时、可用的上游请求编号和 token 用量 |
| `model.retry` / `model.transport_error` | 重试安排、连接或超时失败 |
| `model.completed` | 模型返回结果已经通过本地结构和原文证据校验 |
| `model.failed` | 抽取未成功，附安全的失败原因和调用编号 |
| `model.skipped` | 内置样例、已有抽取结果、解析失败或缺少密钥，没有发送模型请求 |

同一次抽取的多次尝试共用 `call_id`，同一后端请求共用 `request_id`；浏览器 API 响应头也返回 `X-Request-ID`。一个批量抽取请求可能含三份文档，按 `document_id` 区分。日志时间使用 UTC，页面转换为本地时间。HTTP 200 不等于抽取成功，需继续确认 `model.completed`；JSON 或证据校验失败仍记录 `model.failed`。token 未返回时显示未获取，不估算余额或费用。

日志仅保存运行元数据，不保存 Authorization、密钥、文档原文、提示词或模型输出正文。需要核对业务内容时请使用任务中的原文及字段页面。浏览器 F12 网络面板只看得到前端到 FastAPI 的请求，DeepSeek 调用发生在后端，应以上述日志为准。直接载入演示样例不产生付费模型请求；点击样例的提取按钮会记录跳过原因。

## 历史任务与 AI 分工

最近任务列表右侧的删除图标、当前任务工具栏的“删除任务”均打开确认弹窗。确认后删除 SQLite 任务及其专属上传文件，含抽取、规则、AI 建议和人工处理记录；其他任务及共享样例不受影响。请求元数据日志按原轮转策略保留。文件被占用时会明确提示清理未完成。后台处理中删除任务后，过期结果不能恢复该任务。

工作台的“审核引擎”展示三部分：

| 部分 | 实际工作 | 输出与边界 |
| --- | --- | --- |
| AI 文档理解 | 模型从 PDF / DOCX 原文识别采购字段 | 结构及逐字引用验证；显示真实模型、演示预设或人工录入来源 |
| 代码交叉核对 | Decimal 金额运算、字段完整性、型号数量单位、日期与口径判断 | 确定性规则结果，模型不能修改计算或自动审核状态 |
| AI 语义复核 | 进一步比较交付基准、规格文字、验收与付款条件 | 独立建议、解释、摘要及原文证据；每条建议需人工判断 |

确认字段并执行代码核对后，点击“打开 AI 语义复核”→“开始 AI 语义复核”。这会使用后端当前模型配置额外请求 API；即使材料是演示样例，语义复核也必须真实调用模型，没有密钥时明确禁用，不提供预设语义结论。分析输入暂限 160000 字符。模型只能返回结构化建议，不能执行工具或批准采购；这不是自主执行采购的智能体。

语义建议中的文档 ID、位置和逐字引用必须匹配当前材料，关联问题 ID 必须来自当前规则结果。模型返回错误格式、虚构引用、超时或接口错误时显示失败，不静默切换演示结果。引用验证只能证明原文存在，不能保证推断正确。人工可将建议标记为已确认、误报或待处理并备注；存在待处理建议时不能完成整体复核。修改字段或重新核对将使旧 AI 结果失效。分析期间任务发生变更则拒绝采用旧结果。

“调用记录”中跨文档分析标记为“跨文档语义复核”，日志 `purpose=semantic_review`，字段抽取为 `purpose=extraction`。两者复用超时、有限重试及脱敏日志适配层。Word 报告分别展示规则问题和 AI 建议及各自人工状态；未执行语义复核写“未检查”，失败写明原因。

新增 API：`DELETE /api/tasks/{id}`、`POST /api/tasks/{id}/ai-analysis`、`PUT /api/tasks/{id}/ai-findings/{finding_id}`，均要求登录。语义分析失败返回更新后的任务对象（HTTP 200），必须检查 `ai_analysis.status`；HTTP 成功不等于模型分析成功。

## 已知限制

首版仅覆盖同一采购事项、每类一份材料、少量商品。提供单账号会话登录，无 OCR、复杂权限、多租户、支付、企业接口或法律合规审查。服务默认只监听本机，未实现生产部署的并发任务锁、后台队列、细粒度审计身份和备份；不要直接暴露到公网。任务元数据以 JSON 存储在 SQLite 中，文件独立保存。

PDF 最多 100 页，文本最多 100000 字符，DOCX 解压后最多 40 MB；尚未实现隔离解析进程。复杂 PDF 排版、表格跨页、合并单元格、脚注或页眉可能影响提取顺序；DOCX 段落位置指正文段落、表格位置指表格与行号。界面展示解析文本及原文件下载，不包含 PDF 高亮坐标预览。多币种、同义税务表述、复杂交期与模糊商品交给人工复核。
